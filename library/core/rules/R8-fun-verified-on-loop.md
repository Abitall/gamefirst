# R8 — Fun is verified on the loop

Fun is observed when a human plays a running core loop; a document, a trailer, or an agent's opinion can only predict it.

## Why

Nothing in the pipeline can feel bored. A GDD describes intent, a trailer sells an impression, an agent repeats what it was told; none of them can tell you whether the loop holds attention for fifteen minutes. Accept any of them as proof and the first honest test happens after release, when it costs the most. G1 moves that test to the cheapest possible moment.

## The loop

The build must run end to end: input → action → feedback → challenge → reward → repeat. Every step is present and playable. Placeholders, missing feedback, and "we will add it later" do not count: a human cannot judge a step that is not there, and a loop with a hole is not a loop.

## G1

By G1 the loop has had 3–5 iterations. At least one human plays a 15–20 minute build. The agent prepares the build, the protocol, the questions, and the observations; the human plays and judges. G1 records one line and a date: keep, kill, retune, or extend once for this loop. That decision belongs to G1; this rule only requires that it rests on a session, not on a claim.

## Evidence

A session is evidence only with all three:

- a playtest note (D07): the build, what the human did, what happened, their verbatim quotes;
- a capture or video of the running build;
- the build state that was played.

A GDD, a promise, an AI opinion, and a feature list are not evidence: they record intent, not observation. A capture of a menu or a scripted scene is not a loop.

## Boring is a result

A boring or broken loop is a valid outcome. Report it as boring or broken (E09); do not soften it into "needs polish". No human means G1 is blocked, not passed: never invent a session. R1 already refuses an unrun build, R7 allows the one extension when something is there but not yet explainable, and R9 keeps the fix inside the budget. The playtest protocol is in S08, S09, and S10; follow it there.

## Check

- A human played a running build of the loop, not a document.
- The loop runs end to end; no step is a placeholder.
- The playtest note, the capture, and the build state exist and agree.
- G1 has one dated decision line.
- No session, no G1.
