# Marketing pack

## When to load

Before a store page is written, when capsule, screenshots, or a trailer are
briefed, at a wishlist or demo beat, and in the weeks before launch. S13 runs the
release and checks that copy exists and fits; C03 prepares and stops at the store
door; G3 decides ship or hold. This pack writes no final copy, posts nothing,
uploads nothing, and spends nothing.

## Boundaries

- Never post, upload, submit, change a price, send keys, or buy ads. A human
  names the action and the target in an explicit command (R4, E12).
- Never invent reviews, wishlists, followers, awards, quotes, or player counts.
  A purchased or fabricated signal is a lie with a receipt.
- Every claim points to a build, a screenshot, or a measurement. A claim with no
  evidence is cut, not softened.
- Positioning and the final words are creative decisions: this pack names the
  fields and the evidence; a human writes and approves the copy.
- Store rules change. Read the holder's live page on the day of use; a
  remembered size, fee, or policy is not evidence.
- A green selftest proves the files are consistent, not that a page may publish.

Read fresh each time: partner.steamgames.com/doc, itch.io/docs,
developer.apple.com/app-store/review/guidelines,
play.google.com/about/developer-content-policy, and the Xbox, PlayStation, and
Nintendo partner portals.

## Audience and positioning

Answer in order; a blank is a hold.

- Player: who, what they play now, what they will stop playing.
- Promise: one sentence naming what the player does, not a genre label.
- Difference: three things this game does that its reference games do not.
- Proof: for each difference, the build path or clip that shows it.
- Anti-audience: who will not like it; keeping it prevents overclaiming.
- Comparisons: at most three, phrased "for players of X", never "better than X".
- Recall test: one reader repeats the promise back (name, date).

## Store page copy fields

Per storefront; the store's current spec wins over this table.

| Field | Rule |
|---|---|
| Title | the build's name; no subtitle the build does not show |
| Short description | the promise, one sentence, no superlatives |
| Long description | what the player does, features, honest scope |
| Features | 3-6, each with a screenshot or build moment |
| Tags / genre | the store's own vocabulary |
| Languages | shipped and reviewed only; others "planned" |
| Requirements | measured on the minimum target |
| Controls | each declared device tested on this build |
| Descriptors | from the rating questionnaire, not marketing |
| Price / demo / time | a human fills; this pack never sets them |
| Links | press kit, community, site, support: all reachable |

## Capsule, screenshots, trailer

One row per asset: purpose, one-line visual, crop-safe subject, text-safe zone,
source scene, build id, owner, due date. Do not copy pixel sizes into this file;
read the holder's spec page, record its date, then export.

- Capsule: readable as a thumbnail; title legible in the smallest crop; nothing
  where the store overlays text.
- Screenshots: real frames from the named build; one idea each; no UI the player
  will not see; the first states the promise.
- Trailer: 30-60s, gameplay in the first 5s, nothing the build lacks, captions,
  music licence on file, exported at the store's current settings.

## Wishlist, demo, press kit

- Wishlist: a signal, not a promise. Record platform, open date, landing page.
  Never buy, trade, or seed wishlists.
- Demo: one build id, the cut it makes, save behaviour, an end screen pointing
  at the full game. A demo built from another build is a hold.
- Press kit: fact sheet (studio, window, platforms, price or TBA), logo and
  capsule files, 6-10 screenshots, trailer link, key art, contact, credits, and
  licence line. One page, one URL, dated.
- Keys: prepare the recipient list; a human sends (R4).

## Community and launch calendar

Offsets from release; a human sets absolute dates. One owner, one asset per row.

| When | Beat | Done means |
|---|---|---|
| T-8w | page live, wishlist open | page passes the checklist |
| T-6w | press kit and trailer out | kit works logged out |
| T-4w | demo or festival beat | demo build id recorded |
| T-2w | launch post, FAQ, support rota | drafts approved, owner named |
| T-1w | keys, embargo, patch plan | list ready, patch or "none" |
| T-0 | launch post, page check | live on every store, logged out |
| T+24h, T+72h | watch report | crash, reviews, support, next |

Cadence beats bursts: a dated post per beat, one screenshot, shipped things
only, no roadmap promises.

## Claims and evidence

| Claim | Evidence | Where |
|---|---|---|
| feature | build id and path or clip | |
| performance | measurement, hardware, build | |
| amount of content | count from data, not memory | |
| award or quote | source URL, date, permission | |
| player number | store or dashboard export | |

Superlatives need a cited measurement; "coming soon" needs a date and an owner;
a feature cut from the build leaves the copy in the same change.

## Review checklist

Pass / fail / N/A with a path per row; a blank row is a hold.

1. Promise matches the build the player receives.
2. Every claim has an evidence row.
3. Copy fields complete per store; sizes from today's spec.
4. Media from the named build; crops and text-safe zones checked.
5. No paid or fabricated signal behind wishlist, demo, or keys.
6. Calendar rows have owners; press kit URL works logged out.
7. Rating, EULA, privacy, licences present (P01, P03).
8. A named human approved the words and the publish action.
9. Logged-out check on each store and regional variant.

## Holds

Halt on: a claim without evidence; an asset from another build; a fake or
purchased signal; a size or policy remembered rather than read; missing human
approval; a secret in a draft; a price or date the human has not set.
