# gamefirst — быстрый старт

gamefirst — маленький фреймворк для соло-разработки: сначала играбельный
цикл, потом документы. Не «студия в папке» и не пятьдесят страниц GDD до
первого билда.

## Что нужно

- Node.js 20 или новее.
- OpenCode, который понимает V2-массив `permissions`.
- Git — по желанию.
- Windows, macOS или Linux.

## Создать игру

Из папки `gamefirst`:

```bash
node tools/new-project.mjs ../my-game --name "Моя игра" --git
cd ../my-game
```

Открой `my-game` в OpenCode и напиши:

```text
/start
```

`/start` прочитает пять файлов, предложит режим и назовёт первый недостающий
файл. Дальше:

```text
/next      — одно следующее действие
/status    — фаза, активная часть, гейт, блокеры
/verify    — запустить сборку/тесты и записать доказательство
/retro     — короткое ретро после цикла или неудачи
```

## Как идёт работа

1. Идея и один вопрос, на который отвечает прототип.
2. Прототип на 1–2 дня, одноразовый.
3. Одна механика в `gym` с живыми ручками; человек играет и говорит
   `lock`, `iterate` или `kill`.
4. Вертикальный срез: девять пунктов, не «всё сразу».
5. Контент, полировка, релиз — по одному шагу.

Правила простые: не писать документ до работающего кода; одна карточка
системы — одна страница; решение — одна строка с датой; идея вне скоупа
идёт в `BACKLOG.md`, а не в код.

## Что установлено

`new-project` ставит `core` и `game`: 10 правил, 4 агента, 13 навыков,
5 гейтов, 12 eval-задач, 10 инструментов и 6 команд.

Движки и доменные паки лежат в `library/`:

- `library/engines/phaser/` — стабильный, Phaser 4.2.1;
- `library/engines/unity/`, `godot/` — beta;
- `library/packs/` — release, obsidian, art, audio, narrative, localization,
  marketing.

В v0.3 они **не** устанавливаются автоматически: это справочники. Не считай
пак подключённым, если он просто лежит в библиотеке.

## Проверка и обновление

```bash
node tools/verify.mjs ../my-game
node tools/doctor.mjs ../my-game --strict
node tools/upgrade.mjs ../my-game --dry-run
```

`doctor` ничего не меняет. `upgrade --apply` пишет отчёт
`docs/UPGRADE-<from>-to-<to>.md`.

## Чего не делать

- Не просить «сначала опиши всю игру».
- Не заводить GDD на 80 страниц.
- Не добавлять правило/навык/агент без повторяющейся ошибки.
- Не публиковать и не тратить деньги без явной команды.
- Не считать «зелёный» отчёт доказательством: доказательство — артефакт,
  тест, скриншот или запись плейтеста.
